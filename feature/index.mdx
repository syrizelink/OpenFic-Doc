---
title: "索引"
---

索引会将章节切分并转换为向量，帮助 Agent 按语义检索前文。它适合章节较多、难以仅靠标题或关键词找到信息的作品。

## 启用项目索引

<Steps>
  <Step title="选择启用范围">
    于左侧边栏底部打开`设置`，进入`索引`，将`启用范围`设为`全部项目`或`指定项目`。如果只希望索引部分作品，请选择指定项目并勾选对应项目。
  </Step>
  <Step title="选择模型">
    选择一个 Embedding 模型，并按需选择 Rerank 模型。系统提供可以在本地运行的内置模型，也可以使用你自己配置的服务，参阅[创建模型](/getting_started/model)。

    Embedding 负责建立向量与初步检索，Rerank 负责对候选结果再次排序。只配置了语言模型，不能代替这两种模型。
  </Step>
  <Step title="构建索引">
    在`项目索引`中检查章节数量与状态，点击`开始索引`。等待处理完成后，确认状态为`最新`。

    索引过程中可以查看已处理、待处理和失败数量，也可以停止任务。失败时先检查模型连接、向量维度与服务商限流，再重新尝试。
  </Step>
</Steps>

## 分块参数

`分块大小`决定每个索引片段包含多少字符，`分块重叠`用于保留相邻片段之间的部分上下文，且必须小于分块大小。

片段过小可能丢失语境，片段过大则可能让检索结果混入较多无关内容。可以先使用默认值，再根据实际查询调整。

<Warning>
  更换 Embedding 模型或分块参数会使原有索引失效，需要重建。Rerank 只参与检索排序，更换它通常不需要重新向量化章节。
</Warning>

## 自动更新策略

| 策略 | 行为 |
| :-- | :-- |
| 修改后立即 | 章节更新后安排索引更新 |
| 由 Agent 决定 | 由 Agent 在工作时按需要触发索引更新 |
| 不自动更新 | 需要时手动开始索引 |

如果经常批量导入或连续修改正文，可以先完成整理，再统一构建索引。状态显示`过期`或`需重建`时，旧索引不再代表最新正文，请先更新再依赖其结果。

## 索引与其他上下文

索引用于检索相关片段，[摘要](/feature/summary)用于概括章节和区间，[上下文管理](/feature/context)则控制会话中保留多少历史信息。它们解决的问题不同，可以共同使用。

当前索引设置面向章节内容，并不会把所有附件、笔记和世界书都变成同一个章节向量库。查找这些材料时，可以使用对应搜索工具或在消息中直接引用。
