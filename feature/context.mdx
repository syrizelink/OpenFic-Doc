---
title: "上下文管理"
---

会话越长，历史消息和工具结果占用的 Token 就越多。上下文管理用于在保留近期工作信息的同时，降低长会话的占用与请求成本。

于左侧边栏底部打开`设置`，在列表中选择`上下文`，可以分别配置压缩和裁剪。

## 自动压缩

启用`自动压缩上下文`后，系统会根据模型上下文窗口和`自动压缩阈值`，在达到限制前概括较早的对话，保留较近的轮次。

因此，模型元数据中的上下文长度应与实际模型一致。填写过大可能让模型先超出服务商限制，填写过小则可能导致过早压缩，参阅[创建模型](/getting_started/model)。

| 配置项 | 用途 |
| :-- | :-- |
| 压缩模型 | 用于自动和手动压缩，可跟随会话模型或单独选择 |
| 自动压缩阈值 | 以模型窗口百分比计算何时触发压缩 |
| 保留末尾 Token 预算 | 限制保留的近期轮次占用 |
| 保留末尾窗口比例 | 进一步限制近期轮次占模型窗口的比例 |
| 最小可压缩 Token 数 | 可压缩的旧内容太少时跳过压缩 |

末尾 Token 预算与窗口比例会共同约束保留范围。压缩模型的理解能力也会影响摘要质量，复杂或长程任务可以选择更有能力的模型。

## 手动压缩

在主会话处于可操作状态时，可以点击上下文占用位置的压缩入口，手动整理当前上下文。

Agent 正在运行、仍有待处理事项或已经在压缩时，可能无法执行手动压缩；子会话不提供手动压缩入口，但仍可按运行时策略自动压缩。

压缩需要调用模型，会产生请求与费用。如果失败，请先检查压缩模型是否可用，以及相关提供商是否限流。

## 裁剪旧工具输出

`自动裁剪旧工具输出`会在会话运行过程中移除较早的工具结果，避免反复读取大量正文后迅速占满上下文。

`自动裁剪预算`决定尽量保留多少近期工具输出，`自动裁剪溢出阈值`决定旧输出积累到什么程度才触发处理。

压缩会通过模型概括旧对话，裁剪则针对较早的工具输出。它们不会删除项目里的原始章节、笔记或角色资料，需要时 Agent 仍可重新读取。

<Tip>
  压缩摘要无法保留每个细节。重要的设定应保存到角色、世界书、笔记或项目规则中，关键任务也可以重新引用原文，避免只依赖早先的会话。
</Tip>

## 合并系统提示词

`合并系统提示词`可以将连续的系统提示词合并，以改善部分模型或提供商的兼容性。是否需要开启，应根据实际使用的模型和接口判断。

若要调整章节的长期概括，请使用[摘要设置](/feature/summary)，它与会话上下文压缩是不同的功能。
