插件（下称 Plugin）是用于扩展 OpenFic 的独立代码包。你可以通过 Plugin 添加项目统计、编辑器工具、云端同步或自定义 Agent 工作流，而无需修改主应用。

一个 Plugin 通常由清单、Python 后端和视图构成。清单描述它需要什么能力、提供哪些入口；后端处理业务逻辑；视图负责与你交互。

<Note>
本文档以 `feat/extension-host` 分支的 SDK `2.0.0` 为依据，对应提交为 `cdbd1001f7b5c1554f64ef955a65993fcbc0e45b`。插件包仍使用 `api_version: 1`，它与 SDK 版本是两个不同的概念。开始前请使用包含该实现的宿主，已发布版本可能尚未包含全部接口。
</Note>

## 选择你的扩展方式

| 你想要完成的工作 | 建议从这里开始 |
| --- | --- |
| 添加表单、统计面板或设置页面 | [声明式 UI](/plugin-sdk/declarative-ui) |
| 使用 React、Vue 或已有前端应用 | [iframe 与前端 SDK](/plugin-sdk/iframe) |
| 读取章节、创建笔记或处理项目数据 | [业务数据](/plugin-sdk/data) |
| 为编辑器添加按钮并操作当前正文 | [编辑器与宿主操作](/plugin-sdk/editor) |
| 添加工具、提示词处理或自定义执行流程 | [Agent 扩展](/plugin-sdk/agents) |

如果你是第一次开发 Plugin，建议先完成[第一个插件](/plugin-sdk/quickstart)，了解从清单、后端到视图的完整过程。

## 了解运行方式

Plugin 安装在当前连接的后端实例中，前端通过扩展宿主加载入口。因此，同一后端下的浏览器和桌面客户端可以使用已安装的 Plugin，安装时无需重新构建主应用。

界面支持两种渲染方式：

- **声明式 UI**：Python 返回组件树，由宿主使用现有组件原生渲染，适合表单、面板和编辑器工具。
- **iframe**：加载 Plugin 已构建的 HTML、JavaScript 和 CSS，适合需要自行管理前端框架和交互的应用。

同一个 Plugin 可以混用两种视图，也可以只包含后端逻辑。

## 按需声明能力

Plugin 通过 SDK 访问项目数据、存储、网络与编辑器。你需要在清单中声明相应的 `capabilities`，宿主会在调用时检查。

业务资源分别声明读、写能力，例如 `chapters.read` 和 `chapters.write`。写能力不包含读能力。关于清单格式和能力划分，请参阅[插件清单](/plugin-sdk/manifest)。

<Warning>
Python Plugin 在后端进程内运行，是可信代码。能力检查约束 SDK 调用，无法阻止 Python 自行访问进程可达的文件、网络或内部模块。请只安装可信来源的 Plugin，并使用独立开发数据调试。
</Warning>

## 查询当前宿主的接口

当前宿主通过以下接口提供 SDK 版本、能力、插槽、事件、业务操作和 OpenAPI schema：

```text
GET /api/v1/plugins/catalogue
GET /api/v1/plugins/sdk.d.ts
```

在 iframe 内，你也可以使用 `await OpenFic.api.catalogue()` 查询目录。业务请求的路径、字段与组件 Props 应以目标宿主返回的目录为准。
