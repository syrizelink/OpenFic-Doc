Plugin 使用原生 OpenFic ZIP 安装包。分发前请完成源码检查，并将需要的前端资源构建到包内。

## 准备包结构

ZIP 根目录必须直接包含 `plugin.json`，不能再包一层项目目录：

```text
plugin.json
backend/main.py
frontend/index.html
frontend/app.js
frontend/style.css
```

上例是 iframe Plugin。声明式 UI 通常只需要清单与 Python 后端；纯前端或纯后端可以省略未使用部分。

宿主不会在安装时自动执行 pip/npm 安装。依赖和前端产物需要由开发者提前准备，并验证它们能在目标宿主中使用。

## 检查并打包

以下命令在安装了相应版本 OpenFic 的环境执行：

```bash
openfic plugin check ./my-plugin --run-checks --strict
openfic plugin pack ./my-plugin --output ./my-plugin-1.0.0.zip --run-checks --strict
```

仓库开发时，在 `backend/` 中使用 `uv run python -m app.cli` 替换 `openfic`。

严格模式要求处理警告并实际执行已配置检查。若缺少 Ruff、源码脚本或 UI fixture，应先按[开发与调试](/plugin-sdk/devtools)补齐，再分发。

### 安装包限制

| 项目 | 上限或要求 |
| --- | --- |
| 压缩包 | 20 MiB |
| 展开内容 | 40 MiB |
| 条目数 | 512 |
| 入口 | 必须存在，并符合清单规定 |
| 路径 | 拒绝越界、绝对路径与重复路径 |
| 文件类型 | 拒绝符号链接和加密包 |

宿主只接受原生 OpenFic 包，不提供第三方 Mod 的转换或 JS/TS/JSX 后端执行。

## 安装与启用

打开**插件管理**，阅读可信代码说明，确认来源后选择**安装插件包**并上传 ZIP。

安装后默认停用。确认配置后点击**启用**，宿主注册命令并加载视图入口，前端无需重新构建。

Plugin 安装于当前连接的后端实例的 `OPENFIC_DATA_DIR/plugins/`。安装权限沿用应用现有密码模式，不会额外建立多租户项目授权系统。

## 更新插件

在管理页选择**更新安装包**。新包 ID 必须与原 Plugin 一致，版本必须严格递增。

更新保留仍存在的用户设置、启用状态和插件存储。新版本激活失败时，宿主恢复旧代码、配置和命令。普通安装不能使用同版本覆盖；开发服务中的目标 Plugin 才支持同版本热替换。

正在执行的命令会参与生命周期协调。停用或更新前，应考虑耗时任务；已开始的自定义 Graph 或模型请求不会因关闭入口而被强制终止。

## 导出、停用与卸载

导出得到可安装的代码包，不包含运行配置、日志或持久化数据。需要迁移完整运行状态时，请参阅[备份运行数据](/plugin-sdk/services)。

停用后，服务端命令与资源访问立即失效。其他客户端会在刷新插件列表后移除入口。

卸载删除插件代码、配置和存储；生命周期日志单独保留。卸载前请自行备份需要保留的数据。
