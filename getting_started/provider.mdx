<Note>
  在 OpenFic 中，**模型提供商** 与 **模型** 是分离的，你需要先连接模型提供商再创建模型以开始使用
</Note>

OpenFic 基于内置的[目录](https://models.dev/)广泛的支持多种模型提供商，例如 OpenAI、Anthropic、OpenRouter、Infistar 等，通常只需输入你的 API Key 即可。

<Note>
  Requesty 提供商已加入当前仓库，计划随 0.13.0 发布；如果你的版本中没有该选项，请以实际界面为准。
</Note>

任何支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini Generative Language 协议的提供商或是本地模型服务，都可以通过自定义Base URL进行连接。

## 连接一个提供商

<Note>
  在开始之前，请先准备好所要连接的提供商的API Key
</Note>

<Steps>
  <Step title="进入提供商页面">
    于左侧边栏底部打开`设置`面板，此处显示了所有可配置项。

    在左侧列表中找到`提供商`后点击进入。

    <Frame>
      ![Provider Empty](/images/screenshot/provider-empty.png "Provider Empty")
    </Frame>
  </Step>
  <Step title="添加连接">
    点击`新建连接`按钮，在弹出的表单中填写相关信息。

    在`备注名称`处，可以填写易识别的名称，以便于在添加多个相同来源的提供商时做区分，如果不填写，会显示为提供商名称或 Base URL。

    点击`提供商类型`以选择所需的提供商类型，对于绝大多数的提供商，应都能够在其中找到。

    如果所需的提供商不在目录中，可以选择 **OpenAI Compatible**、**OpenAI Compatible (Responses)**、**Anthropic Compatible** 和 **Gemini Compatible** 类型，这几种提供商类型允许你填入**自定义**的 Base URL 以进行连接。

    OpenAI Compatible：基于 [**OpenAI Chat Completions API**](https://developers.openai.com/api/reference/chat-completions/overview) 格式进行连接。

    OpenAI Compatible (Responses)：基于 [OpenAI Responses API](https://developers.openai.com/api/reference/responses/overview) 格式进行连接。

    Anthropic Compatible：基于 [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages) 格式进行连接。

    Gemini Compatible：基于 [Gemini Generative Language API](https://ai.google.dev/gemini-api/docs) 格式进行连接。

    <Frame>
      ![Provider Create](/images/screenshot/provider-create.png "Provider Create")
    </Frame>
  </Step>
  <Step title="验证连接">
    完成填写后，你可以通过点击`验证连接`来确认供应商是否可达。

    在验证过程中，系统会按照所选提供商的协议请求模型列表，例如 OpenAI 兼容接口通常请求 Base URL 下的 `/models`。不同协议的地址与认证方式可能不同。

    <Warning>
      验证连接只用于检查模型列表接口，不能代替实际的模型调用。

      由于并不是所有提供商均提供了可访问的模型获取接口，且部分提供商在访问该接口时并不需要认证 API Key，因此验证失败有时不等同于无法连接，请以实际使用情况为准。
    </Warning>

    <Frame>
      ![Provider Validate](/images/screenshot/provider-validate.png "Provider Validate")
    </Frame>
  </Step>
</Steps>

## 登录一个提供商（OAuth）

OpenAI Codex 提供商支持使用 ChatGPT 账号登录，以使用该账号可用的 Codex 额度，无需填写 OpenAI API Key。账号能否使用相关模型，仍取决于你的订阅、工作区权限和额度。

<Frame caption="选择 OpenAI Codex 后，使用 ChatGPT 登录以开始授权。">
  ![创建连接时选择 OpenAI Codex，显示使用 ChatGPT 登录按钮](/images/screenshot/provider-oauth.png)
</Frame>

<Steps>
  <Step title="选择 OpenAI Codex">
    在`新建连接`中，将提供商类型设为`OpenAI Codex`，然后点击`使用 ChatGPT 登录`。

    如果已有保存的账号或工作区，可以选择已有注册；需要连接另一个账号时，选择`使用其他账户或工作区（新注册）`。
  </Step>
  <Step title="完成浏览器授权">
    在打开的浏览器中登录并完成授权，随后返回 OpenFic 检查连接状态。

    当后端运行在 Docker 或远程服务器上时，浏览器可能无法自动回调。此时点击`手动输入回调链接`，将授权完成后地址栏中的完整回调链接粘贴进去，再点击`完成授权`。

    <Warning>
      回调链接包含一次性授权码，请勿分享。授权有效期为 10 分钟，超时后需要重新开始。
    </Warning>
  </Step>
  <Step title="创建模型">
    连接成功后，前往`设置`中的`模型`，选择刚刚连接的 OpenAI Codex 提供商并创建语言模型。完成授权本身不会自动创建模型或选择默认模型。
  </Step>
</Steps>

如果已连接的账号失效，可以在编辑连接时点击`重新授权`。删除连接会尝试撤销授权；如果提示未确认远程撤销，请同时在 OpenAI Codex 的设置中断开该应用。

## 自定义请求头

如果你的服务商或 API 网关要求额外的请求头，可以在新建或编辑连接时，于`请求头 (可选)`中添加名称和值。

这些值会在服务端加密保存。编辑时不会回显原始值，保留原有项目且不修改值会继续使用已保存的内容，删除该行则移除对应请求头。

请求头应按照提供商要求填写；不要用它们重复配置与所选协议冲突的认证信息。

## 编辑提供商

一旦提供商新建后，其类型将被锁定，不允许更改。

不过你仍然可以修改**备注**、**API Key**和自定义请求头；自定义类型的服务 URL 也可以按需调整。API Key 留空保存时会保留原值。

<Note>
  编辑提供商时，验证连接仍然可用，但出于安全考虑，并不会使用已保存的 API Key，而是使用此时输入框内的值进行认证，因此你需要重新输入 API Key 以重新验证。
</Note>

## 删除提供商

删除提供商后，关联模型将无法继续调用。请检查使用这些模型的默认设置和 Agent，并清理或重新配置遗留的模型。

## 常见问题

### 验证失败，但服务商支持这个模型

请先确认提供商类型与服务商实际支持的协议一致，并检查 Base URL 是否已经包含所需的版本路径。模型列表接口不可用时，可以在创建模型时手动填写模型 ID，再通过`验证模型连接`检查实际调用。

### 本地模型可以打开，OpenFic 却无法连接

模型请求由 OpenFic 后端发出，因此服务地址必须能从后端所在的设备或容器中访问。尤其是在 Docker 中，`localhost`指向容器本身，请按你的容器网络配置填写模型服务地址。
